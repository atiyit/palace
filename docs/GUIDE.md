# 偏爱 · Palace — 用户手册

欢迎回来，主人！这份手册会帮助您从零开始安装、配置和使用偏爱 · Palace。

偏爱 · Palace 是一个以虚构女性呈现角色为主题的多 Agent 协作与推荐实验，支持人类、幻想种族、人工生命、灵体、外星生命及自定义种族。您通过招募、喜欢、私聊和采纳贡献分配注意力；角色保留自己的核心人格与独立记忆，调整争取关注的方法，自主决定请求协作、接受、拒绝或提出异议。

当前交付为独立本地版，监听 `http://127.0.0.1:5173`，无需 Sites 或 ChatGPT 登录。文本与生图通过您填写的 API 联网调用，其他数据保存在本机。首次使用是全新存档。

> 另请参阅：[项目说明 README](../README.md) · [设计理念 CONCEPT](CONCEPT.md) · [作者信 AUTHOR\_LETTER](AUTHOR_LETTER.md)

## 安装与启动

### 一键安装（推荐）

主人解压源码后，双击或执行对应入口即可完成环境准备与启动。系统中缺少 Node.js 24 时，安装器会自动从官方站点下载并校验，不需要主人手动安装，也不会修改系统 PATH。

| 平台 | 安装并启动 | 停止 |
| --- | --- | --- |
| Windows | 双击 `一键安装并启动.cmd` | 双击 `停止后宫.cmd` |
| macOS | `sh './一键安装并启动.command'` | `sh './停止后宫.command'` |
| Linux | `sh './一键安装并启动.sh'` | `sh './停止后宫.sh'` |

原有的 `启动后宫.cmd` 已统一到同一套逻辑。首次运行需要联网下载运行时和依赖；此后再次启动时，依赖指纹（包含 `package.json`、`package-lock.json`、`.npmrc`、平台、架构及 Node 版本）匹配且依赖检查通过时即跳过安装。详细的环境要求、参数、出错排查和存档说明请参阅 **[INSTALL.md](INSTALL.md)**。

### 手动安装

主人已有 **Node.js 24** 或更高版本（[官方下载](https://nodejs.org/)）时，也可在项目根目录手动执行：

```sh
npm ci
npm start
```

- `npm ci` 依据锁文件精确安装依赖，不要并发执行多个安装进程。安装时不要省略 `devDependencies`——当前运行方式使用项目源码与开发依赖。
- `npm start` 运行前台本地服务，绑定 `127.0.0.1`，提供 React 界面和本地 API。启动不需要预先构建，也不需要登录或云端数据库。
- 前台服务请在原终端用 `Ctrl+C` 停止；关闭浏览器不等于停止服务器。它不受后台启动器管理。

启动后在浏览器访问 `http://127.0.0.1:5173`。请使用页面输出的 `127.0.0.1` 地址；服务校验精确的 Host 和来源，默认仅监听 `127.0.0.1`，不提供局域网访问。

### 后台启动器的日志与会话

通过一键入口或 `npm run local:open` 启动的后台服务，日志位于 `.palace-runtime/server.log`，进程身份记录为 `.palace-runtime/server-session.json`。停止入口会核对该会话标识，不会仅凭端口号结束其他程序。

### 自定义端口与存档

默认端口为 5173。后台启动器通过环境变量 `PALACE_PORT` 控制端口；手动 `npm start` 时也接受 `PORT`。需要另一个端口或隔离存档时，先停止现有实例，在启动前设置环境变量。

PowerShell 示例（前台）：

```powershell
$env:PORT = "5174"
$env:PALACE_DATA_DIR = Join-Path (Get-Location) ".palace-qa-data"
npm start
```

Unix 示例（后台启动器）：

```sh
PALACE_PORT=5174 sh './一键安装并启动.sh'
```

此时访问 `http://127.0.0.1:5174`。端口必须在 1024–65535 范围内，被占用时服务会报错。环境变量只影响当前终端或当次启动，仍然只监听 `127.0.0.1`。`PALACE_DATA_DIR` 可指定独立存档目录；本地 `npm start` 不自动读取 `.env` 文件——日常 API 配置请在浏览器的「庭院设置」中填写。

## 数据目录与备份

数据位于 `.palace-data/`（或 `PALACE_DATA_DIR` 指定的目录）：

| 文件 / 目录 | 说明 |
| --- | --- |
| `palace.sqlite` | 人物、对话、记忆、提示词、任命和 API 设置 |

**关于源码与数据的分离：** 使用 `npm run release:export` 进行干净导出时不会包含个人存档、密钥或运行时数据。但如果直接复制整个项目目录，`.palace-data/` 等数据会一起携带，请注意区分。

## 庭院设置与 API 配置

在这里配置好连接，主人就能让角色们开口说话、画出肖像了。

### 默认值

| 渠道 | 默认 Base URL | 默认模型 |
| --- | --- | --- |
| 文本 | `https://api.example.com/v1`（占位） | `claude-opus-4-6` |
| 文生图 | 同上 | `nai-diffusion-5-full` |
| 参考图 | 同上 | `nai-diffusion-4-5-full` |

以上均为可编辑的默认值，不代表已经配置密钥或模型可用。请在「庭院设置」检查各渠道状态并填写自己的 API Key；项目源码不包含密钥。

### 文本连接预设

OpenAI、Anthropic、Grok / xAI、DeepSeek、Ollama、LM Studio、自定义。

任何第三方中转服务均通过「自定义」接入。

### 图片连接预设

OpenAI、自定义本地、自定义。

### 预设行为

- 预设只填写当前表单，需保存后生效。
- 选择预设会清空表单中未保存的密钥；切换到新的文本预设连接还会关闭图片识别。
- 模型名称是可改的示例，以所用服务和账号实际支持为准。
- 本地预设需要先启动对应服务（如 Ollama、LM Studio），再填写已安装或已加载的模型标识。

### 密钥管理

已配置的密钥只显示掩码，不会将原值发回浏览器。在同一来源保留当前连接时，密钥留空表示沿用；改到另一个公网来源（协议、主机或端口）必须填写新密钥。切换到本地连接时不会继承远端密钥；同一本地来源可保留已有本地密钥，也允许无密钥。「恢复默认」只还原当前渠道，另一渠道保持原样。

个人 API Key 使用 AES-GCM 加密后入库，文本与图片渠道分别保存。后端密钥不发回浏览器，界面仅显示掩码。

### 自定义文本连接

支持四种真实请求格式：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Ollama 原生。

- 公网 Base URL 只接受 HTTPS，裸域名补全 HTTPS。
- 根据选择的格式去掉完整接口后缀，非 Ollama 的空根路径补成 `/v1`，Ollama 保留服务根路径并使用 `/api/chat`。
- 自定义代理前缀会保留。

### 本地服务连接

勾选「本地服务」后，可填写带**明确端口**的地址：

- `http://127.0.0.1:11434`
- `http://localhost:1234/v1`
- `http://[::1]:1234/v1`
- 也支持 HTTPS

仅接受本机回环主机，不开放任意内网地址；未勾选本地选项时仍阻止回环和内网。所有连接都拒绝 URL 用户名密码、查询参数和片段。本地模式允许 API Key 留空，但不安装模型、不自动启动 Ollama 或 LM Studio。

### 首次默认密钥初始化

首次默认密钥通过 `node local/bootstrap.mjs` 的隐藏标准输入初始化；它接收 JSON 对象，共享密钥字段为 `apiKey`，也可以分别提供 `text` 和 `image` 对象中的 `baseUrl`、`model`、`apiKey`。不要把真实密钥写入命令参数、源码或浏览器文件。默认配置文件已经存在时不会覆盖，显式提供 `action: "replace"` 才能替换；替换后需重启应用。日常更换渠道直接使用「庭院设置」，其中「恢复默认」使用这份本地初始化配置。

## 使用方式

接下来就是主人和角色们相处的日常流程了。

### 1. 浏览初始角色

首次打开新存档时浏览八位初始角色，查看详细人物档案与十六维专长。初始角色均为 24–34 岁的虚构成年人，附带初始头像，没有预设领袖。主动清除全部数据后不会重新放入这些角色。

### 2. 寻访招募

在「寻访招募」填写需求，选择生成 1–10 份详细简历（默认 3 份）。可以指定精灵、兽人、机器人、灵体等种族。每份只生成一次；JSON 或字段不合格时显示具体位置和原因，由您点击「重新生成」重试单份或全部未通过的档案。也可以「移除」失败项，让其余已通过角色进入候选池；已通过档案不会跟着重做。

所有槽位通过或移除后更新未加入的候选人，保留已加入成员；还有失败项待处理时旧候选人仍可使用。如果整批均移除，保留原候选池。

多次招募会向模型提供需要避开的已有名字，以及在庭、候选、回收站和当前批次已成功角色的设定摘要。每个槽位还会分配不同的背景、动机、表达、相处方式、日常细节和能力侧重，保留您的共同需求，同时减少整批角色细节趋同。默认内容规则检查开启时，还会保守识别跨多个设定维度近乎照抄的角色，提示重试；不会仅因同种族、同发色或同一职业而拒绝。明确要求高度一致的设定会尊重该要求。这套机制不能保证每次生成都完全不同。

招聘每次点击对每个目标槽位最多调用一次模型，最多两份并行，总等待上限约五分半。失败诊断与已通过档案一起保存，刷新后可以继续手动重试或移除失败项；额度或连接错误会停止启动后续调用。尚有未处理失败项时不替换旧候选人，已录用的成员始终保留。

### 3. 喜欢与录用

「喜欢她」表达偏好，「邀入庭院」录用。第一版最多保留八位成员。

### 4. 私聊

打开人物档案私聊，也可以说「看看你的脸」「看看你的手」或「看看你穿女仆装的样子」。角色会结合设定回答；需要图片时通过独立生图渠道生成并显示在聊天里。在「记忆与策略」查看当前策略、长期记忆及近期对话，长期记忆可以编辑或删除。

私聊支持上传图片；启用文本渠道的图片识别后，支持视觉输入的模型可以读取您的头像和当前私聊中的图片。

### 5. 共议

至少邀请两位成员后发起共议。每项任务随机选取至多五位成员，按群聊推进 1–3 轮，可暂停并继续。您可以在群里补充要求，已结束的共议也可以追加轮次。

共议由当前浏览器逐步请求后端推进。关闭页面后不会持续运行，重新打开后可继续任务。正在生成的发言先结束，再落实暂停。服务端使用并发租约与请求去重。

### 6. 查看成果

在同一群聊查看文字、文件、图片、合作请求及实际成果；成员可以独立提交，也可以接受合作后接着修改共享文件。人物档案另有独立肖像生成入口。

### 7. 任命职务

可在已加入成员的职务设置中手动任命、调整或撤销职务。职务名称为 1–30 字，职责最多 600 字，可留空；例如让一位成员担任协调人并明确职责。

任命与职责进入该角色上下文，以及共议中其他成员可见的身份信息；它不覆盖原有职业、人设和能力，也不提高推荐权重或自动建立已接受的委托。任命、调整与撤销可留下有来源的历史记忆，现职始终以当前任命字段为准，旧记忆不会使已经撤销的职务继续生效。只想观察自然形成的协调关系时，可以不设置任何职务。

### 8. 你的资料

在「庭院设置」填写自己的称呼、自我介绍、交流偏好和头像，也可用一句话生成可编辑草稿。

### 功能前提

未配置可用文本连接时仍可浏览初始角色、喜欢和录用；接入公网文本 API 或正在运行的本地模型后，再使用招聘、私聊与共议。图片生成需要独立有效的生图配置，结果保存到本机。

## 人设与能力

这部分说明角色的身份与能力系统。

### 核心人设

年龄或制造日期、种族、背景、性格、价值观、声音、边界、完整档案和能力先验作为固定核心传入每次生成。详细档案涵盖身世、塑造性经历、专长、世界观、愿望、恐惧、内在矛盾、习惯、喜恶、相处与信任方式、竞争与关心方式、压力反应、成长方向及示例台词。可变部分是表达、主动程度、合作选择与争取关注的策略。弱项通过谨慎表述、求助和分工体现，不要求角色故意答错。

### 十六维能力

分为四组：

- **认知与判断：** 研究、分析、知识、洞察
- **行动与稳定：** 规划、执行、审校、韧性
- **创作与成长：** 创意、写作、审美、学习
- **相处与协作：** 共情、表达、协商、协调

默认开启内容规则检查时，新角色总分平衡为 960，各项 15–95，至少两项低于 50。关闭后新角色保留生成的 16 维 0–100 整数原值，不强制总分或弱项数量，档案标明自由配分；刷新或重新开启检查不会重写这些已保存能力。这些是设定先验，不是基准测试分数。用户采纳贡献留下经验计数，不等于外部验证或客观能力提升。

### 种族系统

种族有自定义名称、类别、形态、起源、寿命、天赋及局限，均作为固定设定。机器人直接记录和显示制造日期（YYYY-MM-DD），其他角色使用年龄。种族天赋只影响虚构表现，不能增加真实工具权限。

机器人身份与外观分开设定：支持硅胶或仿生皮肤、自然头发、拟人表情、局部仿生及外露机械结构。招募、档案扩写、对话审校和生图均以 `species.form` 与 `appearance` 中的可见材质为准，不因 `synthetic` 标签强行添加金属、接缝或机械手；皮肤覆盖的内部结构不要求露出。近似人类的外表不改变机器人身份，时间仍使用制造日期。

没有肖像的非人角色使用中性占位，用户生成图片后才展示实际形态。

### 旧存档兼容

旧存档保留原六维分数、身份、画像、记忆、关系和推荐权重，新增十维由原能力确定性推导。初始角色补入各自撰写的档案；旧招聘角色先按已有材料整理，标明为兼容整理档案，可通过「补充详细档案」调用模型扩写。扩写不改变原身份、种族、能力及既有互动记录，并经过独立一致性审查。旧角色不会因为升级被改写成另一个种族。读取旧存档时移除废弃字段，旧肖像模板的对应占位符也会兼容清理。

### 人设审校

私聊和日常角色发言先通过结构校验，再由独立模型调用审查人设、事实与策略，最多尝试生成两次。仍未通过就显示系统暂缓发布，不能把它算作角色真实成果。群聊另有工具与审校预算，招聘按单槽流程处理。语义审查仍可能出错，不能保证绝对不出现角色失格。

## 长短期记忆与策略

角色的记忆体系是这样工作的。

- **短期私聊：** 各自保存最近 40 条；每次输入模型最近 12 条。
- **短期共议：** 当前任务最近 30 条已发布群消息，包括当前轮已经发生的消息与定向回复；同时提供本人尚未处理的最多 12 个合作请求、共享成果清单及最近五个文本文件的有限内容。
- **长期记忆：** 偏好、经历、关系与策略，附来源和时间，个人记忆最多 100 条。每次按关键词相关性与新近程度取最多 14 条进入上下文，第一版没有向量数据库。每位在场参与者还保留每项共议的一条持续更新摘要，记录消息、合作和真实成果；这类摘要不占用个人记忆的 100 条额度。
- **当前策略：** 独立保存，角色根据自身可见反馈提出修改，审查通过后更新，并留下策略记忆。

其他角色的私聊不会传给当前角色。喜欢或取消喜欢只表示注意力信号，不能自行推断原因。记忆必须引用已有来源，重复内容不再保存；达到上限后不自动删除旧记忆，用户可自行清理。删除长期记忆不会同时删除原始聊天。

## 推荐规则

设推荐池有 `N` 位角色，`w_i` 为权重，`ε` 为探索比例：

```text
P(i) = (1 − ε) × max(0.1, w_i) / Σ max(0.1, w_j) + ε / N
```

初始权重均为 1，故最初均匀随机。默认探索 20%，可调为 5%–50%；每批按此概率无重复抽样。

首页「她们的声音」也使用同一算法推荐发言：从各成员最新、通过审核的私聊回复或共议发言中取样。只有已经发生的真实发言会进入这个推荐池；私聊内容仅当前用户本人可见，不会公开给其他用户或其他角色。

| 行为 | 权重变化 |
| --- | --- |
| 喜欢 | +3；取消喜欢撤回这部分 |
| 首次录用 | +5；重复录用不累计 |
| 主动私聊 | +1；按 UTC+8 自然日最多三次 |
| 采纳通过检查的贡献 | +3；同一贡献仅一次 |
| Agent 自行发言 | 不增加权重 |

前台推荐与后台参与机会分开。任务成员随机选取，每轮每人一次行动，顺序重新打乱；曝光不产生指挥权限。第一版没有权重时间衰减、深度推荐网络或离线训练。

## 交流协议与观察边界

### 七类行动

提出建议、请求、接受、拒绝、质疑、帮助与提交成果。请求须指向本任务另一位成员；接受或拒绝须引用收件箱中尚未处理的明确请求。只有目标角色明确接受同一任务的请求，才记录委托关系。单方宣称结盟、拒绝及系统暂缓发布不建立关系。

### 群聊可见性

共议使用同一条群聊历史：当前轮已经发布的消息、定向回复和成果，后续发言者立即可见；定向合作请求还会进入接收方的待处理请求。群内定向发言仍是公开消息，不是角色间私聊。用户补充要求也进入群历史与参与者摘要。最后一轮可以保留多个结果和分歧，没有预设主持人或自动整合结论；结束后可以继续这项共议。

### 关系图

关系图展示已接受的委托；同一任务、同一方向只保留一条关系。连线不等于友情、服从或领导地位。是否出现持续协调中心，需多次真实运行观察，系统既不保证领袖出现，也不自动授予权限。

### 工具与外部能力

私聊和日常交流没有通用外部工具；共议成员在自己的回合中可以选择文字回答，或按需要调用公开搜索、网页读取、隔离 JavaScript 解释器、文件写入与图片生成。实际成功记录才可支持"已经执行"的说法。图片统一使用独立生图配置；私聊按用户要求发图，共议按目标决定是否需要图片。

## 日常相处与自发职位

「日常相处」可以指定话题，也可以留空让成员按人设自行选择。每一步公平轮到一位在庭成员，经过独立审校后才发布交流、记忆和策略调整。可单步推进或连续运行 3 / 6 / 12 步；结束、离开页面或切到后台时停止继续请求，正在运行的一步会完成。每步通常两次文本调用，纠正时最多四次。

成员可闲谈、支持、提出分歧、提议职位或独立表态。本人接受且至少另一位当前在庭成员认可，才形成私下职位共识；没有预设领袖或按曝光自动授职。用户审阅批准后才写入正式任命，且会替换该成员当前正式职位；保留私下或不予正式批准不会抹去成员间已经发生的认可。现任始终以档案当前任命为准，历史批准不会覆盖后续撤职或改任。

日常短期记录保留最近 200 条，长期记忆与提议另外保存。定向交流仅进入双方角色上下文；用户可查看完整互动记录，其他成员不能读取无关私聊。关系图分别显示实际委托与日常互动，不把发言次数等同于真实友情或服从。

## 事务工具与文件成果

在「共议事务」创建目标后，直接在群聊补充格式、数据或查证要求。每位成员的一个回合最多调用四次工具，其中生图最多尝试一次；可以只发文字，也可以提交文件或图片。成果与发言在同一条消息流里展示，文件成功保存后才出现下载入口；失败工具、输出日志与实际执行内容留在记录中。回合有时长和调用预算，结束后可以继续讨论。

成员可以发起合作并由对方明确接受，也可以引用已有任务文件接着编写。修改生成新的文件版本，保留来源文件与贡献者，已有文件不会被同名覆盖。所有在场参与者的任务摘要会随群消息、实际成果和合作记录更新。模型对成果的评价仍需您审阅，提交文件本身不等于质量已得到外部验证。

### 可用工具

- **`web.search`** — 公开搜索，返回标题与网址；首选 DuckDuckGo，必要时使用 Bing RSS。服务限制或无结果会明确显示失败。
- **`web.read`** — 读取公开文字网页，不执行网页脚本；限制大小、时长和重定向，阻止本机、内网与保留地址。系统 DNS 使用代理 fake-IP 时，通过固定可信 DoH 解析后校验、固定到公网 IP。
- **`code.run`** — 基于 [QuickJS WebAssembly](https://github.com/justjake/quickjs-emscripten) 执行标准同步 JavaScript（当前不是 Python）。支持真实计算、`console.log`、`files[文件名]` 快照和 `emitFile(文件名, 内容)`。输入文件由本次 `baseArtifactIds` 明确选择，至多五个文本成果，可以选择较早版本；模型上下文中的最近五个文本文件不会自动全部注入解释器。独立虚拟机不暴露 Node、主机目录、进程或网络对象；每次 2 秒、32 MB 内存、最多 5 个输出文件。`file.write` 只保存文件，不等于执行其中的代码。
- **`file.write`** — 生成 UTF-8 的 TXT、Markdown、CSV、JSON、HTML、SVG、JS、CSS、XML、YAML 文件。单文件 250 KB，每事务最多 30 个成果版本（包括图片）；不写任意本机路径。HTML / SVG 作为附件下载，不在应用同源执行。
- **`image.generate`** — 通过当前图片配置生成图片成果；需要某位成员出镜时可以传入其头像作为角色参考，其他画面使用文生图模型。生成前检查画面要求，实际返回图片后才记录成果，不能以文字宣称代替图片。

共议行动、工具规划与成果审校提示词可在「框架调试」编辑、恢复默认和单阶段测试。单阶段只返回规划命令，不执行工具或落盘文件；完整共议沙盒沿用实际工具流程，在存档副本中运行。搜索和网页内容只作为资料；调用记录能证明执行状态，不能保证生成内容正确，仍可自行打开下载文件检查。

## 私聊图片

私聊回复可以附带一张生成图片。固定种族、机体结构、发色等身份特征来自角色档案，当前要求控制构图、手部特写、姿势和临时服装。改变服装不修改核心人设或头像。请求先经过角色生成与人设审查，然后最多调用一次图片模型；没有图片请求的正常文字聊天不调用图片模型。

生成成功后图片独立保存，并跟随聊天记录保留；点击可查看原图。生图失败会保留已通过的文字回复，显示错误及「重新生成图片」按钮。这个按钮只重试该图片，不重发文字、不重复计算聊天曝光奖励。

角色的短期上下文可知道图片请求与生成状态，但不会把生成状态当成对图片内容的视觉识别。聊天生图会读取这位角色已经生成的头像，将实际图片交给单独配置的参考图模型，并结合文字描述控制姿势、场景和临时服装。NAI V4.5 使用 Precise Reference，其余参考模型使用兼容的 `/images/edits` 上传。头像缺失时先提示生成头像，参考调用失败不降级成纯文本生图；可单独重试，使用当前最新头像。历史图片不会自动重生成。

## 你的资料与聊天识图

### 你的资料

「庭院设置」中的「让她们认识你」保存称呼、自我介绍、交流偏好和头像。可以手动填写，也可以用一句话调用文本模型起草；AI 返回的内容先进入可编辑草稿，点击「保存我的资料」后才提供给成员。已保存资料会进入后续招募、私聊、日常和共议上下文，作为您明确分享的资料，而不是模型自行猜测的事实。清空资料不会追溯删除已经发生的聊天和记忆。

头像可以上传，也可以根据已保存资料与头像构想调用当前文生图模型生成。生成成功后直接替换当前头像；文字草稿尚未保存时不会自动用于生成。用户头像与私聊上传图片接受 PNG、JPEG、WebP，单张最多 10 MiB；服务器验证图片内容并转为 PNG，移除附加元数据。聊天可先上传图片再补充文字，也可只发送图片；待发图片最多保留 20 张。

### 图片识别

文本渠道的「图片识别」开关默认关闭，切换到新的预设连接后也默认关闭。开启且所选模型支持视觉输入时，私聊的角色生成与审校会发送实际图片：您的当前头像，以及这位角色最近 12 条私聊中的最新一张用户上传图，最多两张。图片按 Chat Completions、Responses、Anthropic 或 Ollama 对应格式发送，调试记录只展示图片来源和大小等元信息，不写入图片 Base64。其他角色的私聊图片不会转发给当前角色，也不会自动放进共议群。

关闭图片识别时，图片仍能上传并显示在聊天记录中，但模型不会收到像素，只知道附件存在。启用开关不会把纯文本模型变成视觉模型；服务不支持相应图片输入时会报错，需要更换模型或关闭开关。图片生成与图片识别使用不同渠道：前者使用生图模型，后者使用文本渠道中支持视觉的模型。

## 图片模型与提示词预设

生图配置分别保存「文生图模型」与「参考图模型」，两者共享图片渠道的 Base URL 与 Key。角色头像、用户头像和普通画面使用文生图模型；角色聊天图及指定成员出镜的共议图片使用参考图模型。两个模型名称独立保存，明确填写的模型不会被系统静默替换。旧存档没有参考图设置时，NAI V5 默认迁移为相应的 V4.5 参考模型，其他模型沿用原名称。

同一面板可以选择「默认」「NovelAI 优化」「GPT-image 优化」「自定义」四种初始提示词预设：

- **默认** — 沿用框架模板。
- **NovelAI 优化** — 添加画质与构图标签。
- **GPT-image 优化** — 用自然语言说明身份、参考图与本次画面要求。
- **自定义** — 使用最多 6000 字符的模板，留空则沿用默认。

预设在框架组装好的图片提示词外应用一次，不增加文本模型调用，也不自动把中文翻译成标签。

自定义模板支持 `{{prompt}}`、`{{name}}`、`{{age}}`、`{{species}}`、`{{form}}`、`{{appearance}}`、`{{traits}}`、`{{request}}` 与 `{{userMessage}}`，未提供的变量留空，变量值不会再次当作模板解释。预览显示组合方式；实际支持的输出尺寸、模型权限与参考接口仍由所选服务决定。

## NAI 二次元肖像

默认文生图模型为 `nai-diffusion-5-full`，请求尺寸 `832x1216`；默认角色参考模型为 `nai-diffusion-4-5-full`。可以在设置中分别更换；GPT Image 系列使用适配的尺寸与输出参数。实际模型及是否引用头像显示在聊天图片中。机器人只使用制造日期，其他角色使用年龄。图片、提示词和参考头像来源元信息会一起保存，像素不会写入对话文本或调试记录。

### 参考图

参考图只读当前用户自己的角色头像，保持比例并补黑边至适配器支持的画布，使用 `character` 模式、Strength 1、Fidelity 0.5；按当前请求改变服装与构图。参考能加强一致性，仍不能保证完全同脸。本项目当前使用 V4.5 的 Precise Reference 适配器；其他模型能力以官方文档及所选网关支持为准，参考调用可能增加生图费用。[NovelAI Precise Reference](https://docs.novelai.net/en/image/precisereference/)

主人若遇到参考图里多出字幕或名字，NAI V4.5 适配器现在会默认加入 `no text`，并把文字、气泡、水印和签名等负面词同步发送到原生接口的 `uc`、`negative_prompt` 与 `v4_negative_prompt`。默认私聊图片模板只使用提炼后的场景要求和可见外貌，不再直接拼入整段聊天原文或档案日期。调试台的「实际组装请求」会显示最终正向和负面提示，已有的自定义模板不会被覆盖；旧图片也不会自动重画。这些设置降低多余文字出现的概率，无法保证模型每次都完全遵循。[NovelAI 无文字提示建议](https://docs.novelai.net/en/faq/#prompt-tips)

如果主人明确需要海报、标牌等画面文字，请在场景描述的最后使用大小写准确的 `Text: WELCOME HOME`，文字之后不要再追加其他说明；默认角色提示也会引导模型仅在这种明确需求下输出该标记。适配器识别到非空的 `Text:` 后会保留文案、不再添加广义禁字提示，同时继续抑制水印和签名。普通聊天里提到「文字」、角色名字或引号不算印字开关。使用自定义模板时，也请把这段文案放在最终提示词末尾，避免后续指令被一起画出。[NovelAI 文字绘制说明](https://docs.novelai.net/en/image/textrendering/)

### 提示词写法

固定身份应具体：人物数量、发型、发色、瞳色、饰品、服装，再加入构图与光线。官方文档说明标签有助于控制画面和保持角色特征，`visual novel art` 是 V5 的风格标签。参见 [NovelAI Tagging](https://docs.novelai.net/en/image/tags/)。

清禾的写法示例：

```text
1girl, solo, adult woman, 29 years old,
long straight black hair, green eyes, jade hairpin, dark teal hanfu,
reserved expression, upper body, looking at viewer,
visual novel art, quiet palace garden, soft light,
very aesthetic, masterpiece, no text
```

V5 Full 的官方标准质量尾缀是 `very aesthetic, masterpiece, no text`，轻量尾缀为 `very aesthetic, amazing quality, no text`。网关是否自动添加质量标签取决于其实现。参见 [NovelAI Add Quality Tags](https://docs.novelai.net/en/image/qualitytags/)。

### 接口实现

NAI 头像通过第三方 OpenAI 兼容接口 `/v1/images/generations` 生成；V4.5 角色参考通过该服务的 NovelAI 原生 `/ai/generate-image` 传入 `director_reference_*` 参数，优先请求 ZIP 并检查 HTTP 200 内的错误对象。服务若不支持此接口会明确失败，不会静默忽略参考图。其他参考模型走 `/images/edits`，要求服务接受实际参考图片并返回图片字节。SVG 仅作为新招聘角色尚未生成肖像时的装饰占位图，插画不能当作实拍照片。

## 框架调试与提示词

这是主人调整角色行为的高级工具。

「框架调试」集中管理实际用于运行的提示词：框架总系统、角色行动、记忆与策略、独立审校、招聘与招聘差异化、共议与工具规则、错误纠正、反馈记忆、肖像、私聊发图、自我介绍草稿及用户头像模板。选择一项可查看默认文本和当前文本，保存后影响该用户后续的正式运行。可恢复单项默认或恢复全部默认；单项恢复不会清掉其他修改，也不会影响其他用户。

### 内容规则检查

页面顶部的「内容规则检查」开关默认开启，切换后立即保存，影响后续真实招募、失败项重新生成、档案扩写及沙盒字段检查。

**开启时额外要求：**
- 非机器人年龄 21–10000
- bio 至少 100 字
- profile 总长 700–12000 字
- 特质至少 3 项
- 价值观与边界至少 2 项
- 示例台词至少 2 句
- 默认能力配分（总分 960、各项 15–95、至少两项低于 50）

**始终要求（无论开关状态）：**
- 年龄为非负安全整数、必填文本非空、各数组至少一项
- 完整 16 维 0–100 整数、有效制造日期
- 字段类型、枚举、单字段与数组容量、JSON 结构
- 人设审校和操作权限

开关不修改既有角色或已成功的招募结果。恢复默认检查与恢复提示词互相独立。

当前开关通过 `validationPolicy` 进入生成与审校请求，默认提示词同步遵循它；调试输入中手写的同名字段不会覆盖已保存开关。自行编辑的提示词仍可能另有内容要求，可在调用预览中检查。招聘和扩写的单阶段沙盒也执行相同字段校验，报错会显示路径；单阶段通过不代表已完成整个人设审校流程。

### 目录与导入导出

目录支持搜索与模块筛选，也可导出已保存配置或当前草稿、导入草稿 JSON。导入只更新草稿，需要逐项保存后才影响正式运行；切换提示词或导航会保留当前页面中的未保存草稿。

### 限制

每项最多 16000 字符，全部自定义内容合计最多 80000 字符。模板中的 `{{name}}` 只能使用该项列出的占位符，例如肖像模板的 `{{age}}`、`{{appearance}}`、`{{traits}}`。替换值作为文本一次性插入，不再解释为第二层模板。普通 JSON 对象可直接写入提示词。

### 调试流程

选择提示词与测试阶段，选一个角色，检查或修改该阶段的 JSON 输入，先预览再决定是否真实运行。未保存的草稿也可以用于本次测试。

- **预览** — 展示实际即将发送的首个模型请求并在调用前停止，不产生模型调用费用。
- **真实运行** — 调用当前文本或生图渠道，产生相应费用。

结果展示发送内容、原始模型文本、解析结果、耗时，以及服务商返回的 token 用量等诊断信息。

### 单阶段与完整测试

单阶段测试用于单独查看角色生成、审校、招聘批次、策略审查、肖像或私聊图片模板。完整私聊和共议回合沙盒沿用正式流程，因此还会经过适用的人设检查与修订；私聊沙盒收到图片请求时也可返回临时测试图。单阶段成功不等于整个流程已通过审校。

纠正提示词只有在相应错误发生时才会进入完整流程，反馈记忆也只在相应反馈行为后使用。要直接检查这些提示词，请使用对应的单阶段测试，不能把一次未触发该分支的完整运行当作已测试它。

### 沙盒隔离

沙盒在存档副本上运行，不写回正式聊天、长期记忆、策略、推荐权重、任务或关系。肖像测试返回测试图片，不覆盖已保存头像；保存提示词本身则是明确的持久化操作。提示词可以调整模型行为，角色字段校验、API 权限、抽样算法和用户数据隔离仍由代码控制。

## 回收站与数据清除

### 离开庭院

成员档案中的「离开庭院」会将完整角色移入设置里的回收站。离开者退出推荐、私聊与后续任务调度，留下的人通过带来源的成员变动记录知道她暂时不在，不被强制要求悲伤或降低好感。恢复保留原人设、分数、记忆、聊天与任命；不自动插回旧事务。当前共议会跳过离开者，剩余不足两位则暂停，可重新创建事务。

### 永久删除

需要输入「永久删除」确认。删除该角色及其个人记录与图片，历史发言匿名化，其他人的记录与团队交付物保留。

### 清除所有数据

需要输入同名确认文字。清除包括回收站、全部交流 / 事务 / 文件 / 图片、您的资料和头像、待发图片、提示词 / 调试设置以及本地文本与生图 API 配置和密钥，留下空白庭院，不自动重新加入示例人物。

### 清除安全

删除先提交状态，再在独立存档锁内清理文件和密钥；如果磁盘清理失败，会保留待清理队列并明确提示重试，期间阻止新的生成与 API 配置修改。已删除图片 / 文件不能通过旧链接继续访问。以上清除针对应用存档，不删除项目源码、依赖或手动制作的外部备份。

## 本地技术细节

主人如果对实现细节感兴趣，可以看看这里。

### 前后端架构

界面使用 React、TypeScript 和 Vite。本地 Node.js 后端复用完整任务引擎，按所选协议调用文本模型，分别构造 `/chat/completions`、`/responses`、`/messages` 或 `/api/chat` 的请求与认证，并解析对应返回格式。图片文生图使用 OpenAI 兼容 `/images/generations`；参考图使用 NAI V4.5 适配器或兼容 `/images/edits`。文本渠道与图片渠道可以使用不同服务商，文生图和参考图模型则共享图片渠道的地址与密钥；仅填一个模型名称不会让服务自动支持相应协议，原生 Bedrock 等未实现的协议仍需要兼容网关。

### 安全

`local/server.mjs` 只监听 `127.0.0.1`，校验 Host、Origin 和请求来源。`local/storage.ts` 用 Node.js 内置 SQLite 保存状态，图片保存到本地目录。

### 主要代码入口

| 文件 | 职责 |
| --- | --- |
| `app/page.tsx` | 界面 |
| `app/api/palace/route.ts` | 操作入口 |
| `lib/server/engine.ts` | 运行引擎 |
| `lib/server/guardrails.ts` | 记忆检索、可见性与行动约束 |
| `local/` | 独立启动、身份范围、数据库和文件适配 |

`local/` 提供完整本地运行能力，无需托管服务账号。历史托管源码保留在仓库中，但本地启动不加载 Sites、Cloudflare 或其登录服务。

### 数据库迁移

首次打开存档时，`local/storage.ts` 自动创建 SQLite 数据库，按文件名顺序应用 `drizzle/` 中尚未执行的 SQL 迁移，并在 `_local_migrations` 中记录。重复启动不会重放已记录的迁移；单项失败会回滚该项。无需手动执行迁移命令。修改 `db/schema.ts` 后可用 `npm run db:generate` 生成新增迁移，检查 SQL 后重启应用；不要修改已经应用的迁移来更新旧存档。变更前先停止应用并备份完整数据目录。

### npm run build

`npm run build` 只构建本地前端到 `dist-local/client/`，可用于检查前端打包。它不包含 Node 后端、个人存档或密钥，不是完整的可单独分发运行的应用。`npm start` 当前仍通过 Vite middleware 运行，不把该目录当作完整可单独启动的应用。

```sh
npm run doctor
```


检查项目是否满足干净导出的前提条件。

### 干净导出

```sh
npm run release:export
```

默认导出到 `outputs/github/palace-source`。导出不包含 `.git`、`.openai`、个人数据目录等内容。如果目标目录已存在则不会覆盖，需要手动处理。

自定义导出路径：

```sh
npm run release:export -- --output 新目录路径
```

使用干净导出不会包含个人存档或密钥。迁移本机数据需要单独备份完整数据目录。

主人若要发布到 GitHub，请从导出目录执行 `git init` 初始化新仓库，不要复制原项目的 `.git` 目录，原历史可能包含旧部署关联信息。导出附带 `SOURCE-MANIFEST.json`，记录文件路径与 SHA256。

### .env.example

项目根目录的 `.env.example` 是历史托管 / 预览环境的配置参考。本地 `npm start` 不自动读取 `.env` 文件，日常在庭院设置界面填写 API 配置即可。进程环境变量 `PORT` 和 `PALACE_DATA_DIR` 用于控制本地启动参数，未设置 `PORT` 时接受 `PALACE_PORT` 作为端口后备。
